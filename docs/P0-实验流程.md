# P0 实机验证流程

状态：待执行。当前已完成的无权限验证与结果见《P0-验证记录》。

## 实验范围

用一个可恢复的 Mac 实验环境和至少一个获授权的客户端验证。第一轮以一个明确网络接口、端口 18080（TCP/UDP）和对照端口 18081（TCP）进行；这是对原型的验证范围，不是最终产品的所有接口覆盖承诺。

## 先读取实际系统状态

普通用户运行 `pf-probe doctor`。如果需要继续实机实验，再通过 macOS 管理员授权运行 `tools/privileged-preflight.sh`。该脚本只读 PF 状态、主规则与 anchor 信息，不启用 PF、不加载规则、不清理连接。

管理员授权由 macOS 控制。不要把密码写进项目、命令参数或聊天。

## 挂载门槛

当前没有自动 root anchor 挂载器。需要先检查实际规则集，确定可以安装一个独立引用，且未配置端口的现有规则保持原有行为。

不能直接执行 `pfctl -f examples/...` 把 anchor 内容作为主规则集；也不能通过清空所有 PF 规则来方便测试。仅向任意命名 anchor 加载规则而没有 root 引用，同样不能视为生效。

生成器含 `quick` 放行/拒绝规则：它只适合挂在已审查的位置。早于它的 quick 规则、已有状态、其他过滤层、后续反向状态都可能影响效果。真实安装器须对冲突做明确处理后，才能将这部分能力交付给普通用户。

## 流量实验

1. 按 README 启动测试服务，记录未限制时两条 TCP 与单向 UDP 的计数。
2. 将客户端的实际来源 IP 配置到白名单，替换示例中的文档地址；修改前保存本软件的实验配置和实际状态快照。
3. 在已经审查的 root anchor 位置应用实验规则，确认白名单内的新连接仍可访问。
4. 用另一来源验证拒绝；若只有一个客户端，可在清理已有状态后，用两组明确的策略和新连接分别验证允许与拒绝。
5. 保持客户端原先的 18080/TCP、18081/TCP 和 18080/UDP 通信。
6. 将客户端从所有覆盖它的白名单中移除，先确认阻断规则已应用，再运行精确状态清理实验。
7. 记录保存配置、系统规则应用、状态清理返回、最后收到数据的时间。允许统计窗口里的已在途数据，不把显示刷新间隔当成网络阻断耗时。
8. 核验 18080 后续数据停止，18081 持续通信；UDP 是一次请求启动的下行流，不能依赖新请求来触发检测。
9. 核验 PFLOG 来源、端口、协议、action 与实验相符；记录采集/解析丢失统计。
10. 仅撤除本软件的实验规则、引用和引用计数，验证原先其他端口的行为。完整的安装/卸载恢复仍是后续工作。

## 必须另外测试的情况

- 先建立连接再启用端口管理。
- IPv4 与 IPv6、TCP 与 UDP。
- 相同来源通过其他未配置端口持续传输。
- 空白名单、多个网段重叠、删掉单 IP 后仍被网段覆盖。
- 反向数据重建状态、系统已有宽泛放行或 quick 规则。
- 退出界面、后台异常、系统重启；当前 CLI 不承担常驻服务职责。
- 未经签名/公证的内部安装流程；当前尚未制作安装包。

任何一项失败，都不能降低已确认的撤权或日志要求来宣称 P0 通过。
