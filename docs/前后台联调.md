# 前后台联调记录

日期：2026-11-12

范围：React 界面（前台）↔ Tauri 2 / Rust 命令层（后台）↔ 本机 SQLite。系统 PF 规则挂载、后台常驻服务和真实访问日志采集不在本轮范围内。

## 1. 结论

- 桌面端可以启动，WebView 正常加载 `http://127.0.0.1:1420` 的 Vite 开发页。
- 首次打开空数据库时，界面读取到 `null` 后注入演示数据，并在 350 ms 防抖后通过 `save_state` 写入 SQLite：5 条规则、5 条操作、6 项偏好。
- 重启桌面端后，界面能从 SQLite 读回状态并回写，未被演示数据覆盖。
- 前端生产构建与 Rust 后端单元测试均通过。
- 另用 GitHub Actions 的 `windows-latest` 构建了 Windows 预览安装包，仅覆盖界面与 SQLite，不含 WFP 执行层。
- 浏览器预览仍只使用 `localStorage`，不能直接访问 SQLite；真实联调必须使用桌面端。

## 2. 链路

```text
React 页面 / Zustand
  └─ ui/src/bridge.ts（invoke）
       └─ src-tauri/src/commands.rs
            └─ src-tauri/src/store.rs（rusqlite）
                 └─ port-guard.sqlite3
```

`ui/src/bridge.ts` 用 `isDesktop()` 判断运行环境：

- Tauri WebView：`__TAURI_INTERNALS__` 存在，走 IPC。
- 普通浏览器：只读写 `localStorage`，不会调用后台命令。

## 3. IPC 契约

命令定义在 `src-tauri/src/commands.rs`，参数与返回值统一使用 camelCase。

| 命令 | 请求 | 成功返回 | 说明 |
| --- | --- | --- | --- |
| `load_state` | 无 | `PreviewState \| null` | 空库返回 `null`，界面据此注入演示数据 |
| `save_state` | `{ payload: PreviewState }` | `null` | 写入前用共享规则核心重新校验 |
| `reset_state` | 无 | `null` | 清空规则、操作和偏好 |
| `preview_policy` | `{ payload: PreviewState }` | `string` | 返回独立 PF anchor 文本，不加载规则 |
| `app_info` | 无 | `AppInfo` | 版本、平台、架构、数据库路径、运行时 |

`PreviewState` 结构：

```ts
{
  rules: Array<{
    id: string
    name: string
    port: number
    protocols: Array<'tcp' | 'udp'>
    sources: Array<{ address: string; label: string }>
    enabled: boolean
    updatedAt: string
  }>
  operations: Array<{
    id: string
    time: string
    action: string
    detail: string
    port?: number
    result: '成功' | '失败'
  }>
  preferences: {
    interface: string
    logInterface: string
    retention: '7' | '14' | '30'
    launchAtLogin: boolean
    notifyBlocked: boolean
    notifyLogGap: boolean
  }
}
```

后台校验失败时命令返回字符串错误，界面在保存 toast 或加载横幅中展示，不写入数据库。主要约束：

- 规则 `id` 非空且唯一，名称和 `updatedAt` 非空。
- 每条规则至少一个来源，协议至少选择 TCP 或 UDP。
- 地址由 `pf-probe` 规则核心校验并规范化。
- 来源总数不超过 2000，操作日志不超过 200 条。
- `retention` 只能是 `7`、`14`、`30`。

## 4. 启动联调

```sh
# Node.js >= 20.19；仓库 ui/.nvmrc 为 24
fnm use 24

npm install
npm --prefix ui install

# 同时启动 Vite 和 Tauri 桌面窗口
python3 tools/desktop.py dev
```

只调界面外观、不涉及后台时：

```sh
npm --prefix ui run dev   # 浏览器打开 http://127.0.0.1:1420
```

macOS 数据库路径：

```text
~/Library/Application Support/dev.portguard.desktop/port-guard.sqlite3
```

设置页“运行状态 → 本地存储”会显示实际路径。删除该文件等同于清空本机预览数据；也可以在设置页使用“恢复演示数据”。

## 5. 本轮验收记录

| 检查项 | 操作 | 结果 |
| --- | --- | --- |
| 前端构建 | `npm --prefix ui run build` | 通过（Vite 8.3.8，主包 gzip 约 205 kB） |
| 后端单测 | `cargo test -p port-guard-desktop` | 3 项通过（渲染、校验、持久化） |
| 桌面启动 | `python3 tools/desktop.py dev` | 窗口进程启动，Vite 监听 127.0.0.1:1420 |
| 首次空库 | 使用全新应用数据目录启动 | `load_state` 返回 `null`，自动写入 5 条规则、5 条操作、6 项偏好 |
| 重启恢复 | 直接修改数据库中规则名和接口为哨兵值后重启 | 界面读回并回写哨兵值，未被演示数据覆盖 |
| IPC 失败兜底 | 静态检查 | 加载失败显示错误横幅且不覆盖数据库；保存失败显示 toast 并保留“写入失败”状态 |

本轮未做鼠标级 UI 自动化（当前环境没有可用的辅助功能/截图授权），也没有调用 `preview_policy`；该命令目前仅由 Rust 测试覆盖，界面尚未提供入口。

## 6. Windows 预览包

2026-11-12 额外在 GitHub Actions 的 `windows-latest` 上构建了 Windows 预览包，工作流为 `.github/workflows/windows-build.yml`，核心命令：

```powershell
npm ci
npm --prefix ui ci
npx tauri build --bundles nsis
```

产物：

- `Port-Guard-0.1.0-x64-setup.exe`：NSIS 安装包，约 2.8 MB。
- `Port-Guard-0.1.0-portable.exe`：未安装的便携版，约 10 MB。

Windows 包只用于界面与本地 SQLite 联调，**不包含 Windows WFP 或防火墙执行层**；设置页中的 PF 引擎、日志采集和主规则挂载仍是示例。安装包没有代码签名，首次运行可能出现 SmartScreen 提示。

为了让项目能在非 macOS 目标上编译，本轮做了两处平台限定：

- `build.rs` 只在 `CARGO_CFG_TARGET_OS=macos` 时编译 `native/pf_native.c`。
- `src/lib.rs` 只在 macOS 上导出 `native` 和 `update` 模块。

Windows 数据库通常位于 `%APPDATA%\dev.portguard.desktop\port-guard.sqlite3`，以设置页“本地存储”显示为准。

## 7. 已知边界

- 访问日志页面仍是 `ui/src/data.ts` 中的演示事件，没有接入 `pf-probe capture` 或 pflog。
- 设置页的运行状态、PF 引擎、日志采集和主规则挂载仍标注为示例。
- 保存只代表写入 SQLite，不代表 PF 规则已加载或已生效。
- 浏览器预览与桌面端是两套存储，不要用浏览器页面的结果判断后台是否写入成功。
- 本轮只在 macOS 上实际运行；Windows 只构建了界面/SQLite 预览包，WFP 执行层仍未实现。

## 8. 排障

1. 桌面端启动时出现“无法读取本机 SQLite”横幅：先点“重试”，再检查数据库文件权限和磁盘空间；此时界面修改不会写入本机存储。
2. 保存失败 toast 显示校验错误：按提示修正规则，例如地址格式、协议为空、重复 id 或超过来源上限。
3. 需要干净状态：退出桌面端后删除 `port-guard.sqlite3`（连同 `-wal`、`-shm`），或在设置页恢复演示数据。
4. 自定义 `HOME` 或在沙箱中运行时，WebKit 可能输出缓存目录权限警告；只要 SQLite 能正常读写，该警告不影响 IPC 联调。
